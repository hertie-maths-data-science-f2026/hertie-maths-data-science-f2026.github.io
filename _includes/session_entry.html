The order is the same everywhere and is the point of this file existing: 1. heading - the ordinal ("Session 3") and, when the schedule declares one, the name 2. body - the learning objectives, then whatever the page passes as `extra` (Readings passes the citation list) 3. links - the files, last. They used to sit up beside the heading, where they crowded the title and made the description read as an afterthought. How a file link renders - the name to the hosted copy where there is one, and the chevron menu after it (View here for a hosted copy, View on GitHub, Edit in browser, Edit in the reader's editor) - is `file_link.html`, shared with the Updates box and the All Materials tree. `include.section`, when given, is the singular section noun ("lecture", "lab", "reading") that selects which of the entry's links belong to this page, matched against each link's own `section` field - the open-courseware site's pages still pass it. A semester site's kind tab passes none: a row is one entry of one kind, and every link it carries is its own. `include.skip`, when given, is a section noun whose links are left out: a lecture's own tab skips "reading", so the readings attached to it show on the Readings tab only. "None" arrives as nil (kind.html passes `section=only` with `only` unassigned), so the guard tests `== nil`. It must not test `== blank`: Liquid 4 (GitHub Pages) answers that by calling Ruby's `blank?`, which only Rails defines, so `nil == blank` and `"" == blank` are both false there and the list rendered empty on every kind tab. {%- endcomment -%} {%- assign entry = include.entry -%}
